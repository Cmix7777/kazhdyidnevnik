# Каждыйдневник

Личное Android-приложение на двоих: расписание пар, смены, план учёбы, прогресс и дедлайны.
Две страницы со свайпом между ними: слева моя, справа второго человека, для которого приложение тоже сделано.

## Что внутри

- Kotlin + Jetpack Compose (Material 3), тёмная и светлая тема (переключатель в настройках, можно «как в системе»): у моей страницы фиолетовая, у второй сиреневая с небесно-голубым
- Одно приложение на двух телефонах: при первом запуске оно спрашивает, чей это телефон; свои уведомления приходят владельцу, про второго человека — по желанию
- Шрифт Manrope (SIL Open Font License 1.1, текст лицензии в `licenses/Manrope-OFL.txt`)
- Моё расписание берётся с открытого сайта колледжа timeo.mveu.ru, расписание второго человека — из таблицы Excel на сайте его колледжа; .xls и .xlsx читаются без сторонних библиотек
- Свои дела (работа, вождение, учёба и другое): разовые или каждую неделю, с напоминанием заранее; можно и через полночь, например с 23:00 до 02:00
- Дорога: до колледжа выходят раньше, до работы позже (время на дорогу у каждого своё и задаётся в настройках)
- Дела второго человека: телефоны связываются один раз кодом (Настройки → Связь), дальше дела обмениваются сами через бесплатное облако Firebase (Firestore, тариф Spark, без аккаунтов и карты): при открытии приложения и примерно раз в 3 часа. Хранится только расписание дел и смен, без заметок, бюджета и дат, и оно шифруется на телефоне (AES-256-GCM, ключ выводится из кода связи): в облаке лежит нечитаемая строка, а сам код туда не уходит. Передать дела сообщением вручную тоже можно
- Бюджет: доходы и траты с категориями, остаток по дням на графике, статистика за месяц
- Важные даты можно добавлять и менять прямо в приложении
- Данные, дела, бюджет и прогресс хранятся на телефоне (в облако уходит только то, чем делишься со вторым телефоном)
- Фоновая проверка расписания (23:00, 6:30 и примерно раз в 3 часа) и уведомление, если пары изменились
- Напоминания: утренняя сводка, начало блоков учёбы, вечерняя отметка сделанного
- Погода в Ижевске (open-meteo.com): сейчас и по часам, погода при выходе и на обратном пути с советом, что надеть, предупреждения (гололёд, сильный ветер, снегопад), прогноз на неделю и уведомление о погоде на завтра
- Обновление прямо из приложения: оно само находит новую версию в Releases
- Автокопия прогресса раз в день в «Загрузки/Каждыйдневник» и восстановление из файла
- Сборка, тесты и выпуск версий — GitHub Actions

## Как установить

1. Открыть на телефоне раздел [Releases](../../releases) этого репозитория.
2. Скачать `kazhdyidnevnik.apk` из последней версии.
3. Открыть файл и разрешить установку.

Дальше обновления ставятся из самого приложения: «Настройки» → «Обновления».

## Как идёт разработка

Каждый пуш в `main` запускает тесты и сборку. Если ключ подписи задан в секретах репозитория, автоматически выходит новая версия в Releases.

Секреты репозитория (Settings → Secrets and variables → Actions):

- `SIGNING_KEYSTORE` — ключ подписи в base64
- `SIGNING_PASSWORD` — пароль ключа

Ключ подписи хранится только у владельца. Без него нельзя выпускать обновления, которые встанут поверх установленной версии.

## Облако (Firebase)

Проект Firebase `kazhdyidnevnik` (Firestore в Европе, тариф Spark, анонимный вход). Приложение ходит в него по REST, без библиотек Google (`data/CloudShare.kt`).
Правила базы разрешают читать и писать только документы `shares/<имя из кода>-<кто>` длиной имени 20–60 знаков с двумя полями (`payload`, `updatedAt`); список документов и удаление закрыты:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /shares/{shareId} {
      allow get: if request.auth != null && shareId.size() >= 20 && shareId.size() <= 60;
      allow create, update: if request.auth != null && shareId.size() >= 20 && shareId.size() <= 60
        && request.resource.data.keys().hasAll(['payload', 'updatedAt'])
        && request.resource.data.keys().hasOnly(['payload', 'updatedAt'])
        && request.resource.data.payload is string && request.resource.data.payload.size() < 300000;
      allow list, delete: if false;
    }
  }
}
```

### Шифрование

Код связи (`kds-xxxxx-xxxxx-xxxxx-xxxxx`, 20 случайных знаков) создаёт один телефон и пересылает другому в мессенджере. Из него по HKDF-SHA256 независимо выводятся два значения (`data/CloudCrypto.kt`): имя документа (32 знака шестнадцатеричной записи плюс `-aizat` или `-nastya`) и 256-битный ключ AES-GCM. По имени документа, которое видит сервер, ни код, ни ключ не восстановить, а сам код в облако не отправляется. Поле `payload` хранит строку `KE2:` и зашифрованные дела; одноразовый номер новый при каждой отправке, а имя документа входит в проверяемые данные, поэтому документ нельзя подменить документом другого человека.

Коды старого вида `kdp-...` (версии до 1.0.15) не принимаются: тогда код был частью имени документа и сервер его видел. После обновления связь создаётся заново.

## Тесты

Обычные тесты (расчёты, разбор расписания, обмен с облаком, шифрование) запускаются при каждой сборке: `gradle testDebugUnitTest`.

Тесты экранов (`app/src/androidTest`) запускают приложение на эмуляторе Android и нажимают на кнопки, как человек: выбор владельца телефона, вкладки, добавление дела, настройки, тема, вставка кода связи, страница второго человека. Они идут отдельным процессом на GitHub (`.github/workflows/ui-tests.yml`), сборка и выпуск версии от них не зависят. Итог каждого запуска попадает в файл `status-ui.txt` ветки `ci-status-ui`, а подробный отчёт лежит в файлах запуска (Actions → «Тесты экранов» → ui-test-report). Для запуска на своём компьютере нужен эмулятор или телефон: `gradle connectedDebugAndroidTest`.
